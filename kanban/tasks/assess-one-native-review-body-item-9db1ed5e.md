# Assess one native review-body item through the existing rejection boundary

## Context

Services [PR99 review5557123176](https://github.com/open-hax/services/pull/99#pullrequestreview-5557123176)
contains three stable CodeRabbit item IDs on source
`5b753995fdf2f8427d753ac0200b61abb5e0e9d8`. The current canonical gate
retains their conservative obligations. Native positive prose is not itself a
settlement, and the complete body does not satisfy the existing bounded positive
body format. The existing independent rejection grammar can name a review/item,
but its current request, full-context selection and ETA transport admit only real
PRRT thread/root-comment inputs. There is no demonstrated body-item transport.

The existing `opencode-mimo-evidence-review-agent` card owns the central reviewer
and earlier thread-shaped repairs. Its retained scope does not grant this new
input kind. This proposed standalone card owns only the missing adapter. The
existing trusted-publication plan (personal ETA PR22) remains separate.

## Outcome

An already admitted repository/PR can request an independent assessment of
exactly one real native review-body item and one actual authorized User proposal.
The assessor may agree, disagree or refuse. A genuine accepted native agreement
can subsequently be consumed by the unchanged item-settlement law; no local
judgment, model approval or successful job clears an item by itself.

  in the existing canonical APIs, plus complete review-body collection using

  `skills/pr-flow/scripts/pr_flow/law.cljc`, `native_context.cljs`,

  `eta_mu.law/infra.rejection_assessment` namespaces. Consume a real protected,

## Non-goals

Grouped items or multiple writes per invocation; whole-body finding inputs;
fake threads; parser aliases; severity/quorum/positive-format changes; automatic
settlement/resolution; source/ledger restyling; provider, model, credential, App,
budget or permission changes; new Muse tools; application/caller/deployment
changes. Existing Services99 findings, the original inline P1 and historical
failed assessments remain unchanged. CodeRabbit self-amendment is not assumed.

## Acceptance criteria

1. Existing thread-mode controls remain valid. Body mode rejects missing,
   malformed, duplicate or extra scopes before any model/publication effect.
   Missing exports, imports, prerequisites or compiler errors are not causal RED.
2. Canonical selection binds the complete authored review/body, native node and
   database IDs, configured Bot identity, state, immutable review commit,
   submission and latest edit time. REST/GQL values must agree. The selected ID
   must occur in the live native body; quoted/generated or unknown IDs refuse.
3. Collect every page of native reviews, threads/comments, issue history and
   applicable canonical history with truthful completeness. Bind current head,
   full changed-source inventory and relevant unchanged source/tests. A stale,
   partial, edited, conflicting or unavailable input refuses rather than falling
   back to a selected paragraph or an assumed empty history.
4. Select the latest matching actual authorized User proposal, including edits;
   preserve substantive Reason/Evidence, independent-principal and chronology
   laws. Judge the actual recommendation, including a no-additional-change
   proposal about verified preservation. An adverse or uncertain judgment is
   retained and must not manufacture an agreement.
5. Keep anonymous dynamic eligible free-MiMo discovery, existing stage/tool,
   whole-input, canonical/Muse pin, accepted-invocation and terminal guards.
   Verify the existing pinned profile accepts the text/summary carrier; if not,
   stop and revise the reviewed scope rather than altering Muse implicitly.
6. Recollect current native scope/history before and after the sole publication.
   Wrong actor, self-corroboration, head/body/proposal/edit races, stale or disputed
   agreement and an ambiguous POST stop without automatic replay. Only the
   actually retained native comment/readback can become agreement evidence.
7. A later, distinct authorized User final disposition must independently pass
   the existing item-specific settlement law. Assessment supplies no approval,
   review coverage/cohort/round, check, source-adoption or deployment credit.
8. Preserve all historical events, item IDs, failed runs and unresolved scopes.
   Before operational use, qualify adopted canonical/controller sources and a
   genuine accepted native invocation/publication for the exact current target;
   refusal or disagreement remains an honest outcome, not permission to waive.
